# Design specificity verdict

**LLM assessment:** A dark operations console suits moderators, and coral is specific to 4LIFE. The implementation does not apply that identity consistently: purple remains in the MUI theme and sidebar while dashboard, requests, and users each add local color systems. The details feel category-standard rather than built from one 4LIFE system.

**Deterministic scan:** `impeccable detect --json src` reported 230 advisory findings: 176 undocumented color values and 54 radius values outside DESIGN.md. Most are in users (35), settings (30), locations (25), amenities (24), and login (24). This supports the system-drift finding. These are token mismatches, not proof that each value is inherently bad.

**Visual inspection:** Dashboard screenshot confirms the dark shell, compact left navigation, and metric cards. At the captured narrow viewport, navigation labels appear clipped. `/requests` and `/users` did not finish rendering in direct browser inspection, so those were assessed from source.

# Overall impression

The product has a sound dark foundation and task-oriented structure. The biggest opportunity is to make the documented 4LIFE coral and neutral palette the actual shared system, then make identity review safer and faster.

# What is working

- Persistent labeled navigation supports frequent movement between admin areas.
- Request queue includes skeleton, empty, error, retry, and per-action loading states (`src/pages/request-mod/index.tsx`).
- Users page has search, role filters, sorting, page size, and result counts (`src/pages/users/index.tsx`).

# Priority issues

- **[P1] Resolve competing color and shape systems.** Shared theme still defines `#5865F2` while DESIGN.md names coral; pages add more literals. Active, focus, and primary states become unpredictable. Centralize brand, surface, border, and semantic tokens and migrate page styles. Suggested command: `$impeccable colorize`.
- **[P1] Make identity review safer.** Request cards expose Approve and Reject, while full document comparison lives on another route. A moderator can approve before inspecting both ID sides. Make application detail the primary action and place decisions after document and profile review. Suggested command: `$impeccable shape`.
- **[P1] Fix responsive navigation and dashboard density.** The observed narrow view clips navigation labels and metric cards stack into tall full-width panels. Use a small-screen drawer/menu and compact metric grid with explicit tablet/mobile breakpoints. Suggested command: `$impeccable adapt`.
- **[P2] Standardize language and status vocabulary.** Users screens use Vietnamese while dashboard and moderation remain English; status colors also compete with brand purple/coral. Use one language per locale and reserve semantic colors for outcomes. Suggested command: `$impeccable clarify`.
